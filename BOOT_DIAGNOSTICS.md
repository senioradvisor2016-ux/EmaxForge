# EMAX II Boot Diagnostics — Problem och Lösningar

**Datum:** 2026-03-03  
**Problem:** ZuluSCSI och EMAX 2 bootar inte korrekt

---

## 🔍 IDENTIFIERADE PROBLEM

### 1. **ZuluSCSI Config är Felaktig** ❌
**Problem:**
- Config genereras bara med `[SCSI1]` utan vendor/product/sectorSize
- Config saknar `[SCSI0]` för boot disk (HD0)
- Config genereras inte för alla SCSI IDs när multi-image setup används

**Lösning:** ✅ FIXAT
- Använder nu `ZuluSCSIConfigService.generateConfig()` istället för minimal config
- Genererar config för alla SCSI IDs (0, 1, 2, etc.)
- Inkluderar korrekt vendor/product/sectorSize för varje SCSI ID

**Kod ändring:**
```swift
// FÖRE (felaktig):
let minimalConfig = """
[SCSI]
EnableParity = 1
[SCSI1]
"""

// EFTER (korrekt):
let configService = ZuluSCSIConfigService()
let configContent = configService.generateConfig(for: appState.currentDevice, images: createdImages)
```

---

### 2. **Boot Signature** ✅
**Status:** Korrekt
- Boot signature värden är standard tools-verifierade och size-specific
- Placerad på offset 0x1FE och 0x1FF (standard position)
- Värden varierar per diskstorlek (korrekt)

---

### 3. **OS Placement** ✅
**Status:** Korrekt
- OS skrivs till cluster 1 (korrekt)
- Cluster offset beräknas som: `clusterAreaStart + clusterSize`
- FAT entry 1 = 0x7FFF (END marker, korrekt för single-cluster OS)

---

### 4. **Catalog Entry** ✅
**Status:** Korrekt
- OS catalog entry har field C = 0x0081 (CRITICAL flag, korrekt)
- Bank index = 30720 (special value för OS, korrekt)
- Start cluster = 1 (korrekt)

---

## 🔧 ÅTGÄRDER TILLAGDA

### Fix 1: Korrekt ZuluSCSI Config Generation
**Fil:** `BootableDiskWizard.swift`
- Använder nu `ZuluSCSIConfigService` för att generera korrekt config
- Genererar config för alla SCSI IDs som används
- Inkluderar vendor/product/sectorSize för varje SCSI ID

**Exempel på genererad config:**
```ini

SelectionDelay = 255

; Startup delay (ms) — wait before responding

[SCSI0]
Vendor = E-mu
Product = EMAX II HD
SectorSize = 512

[SCSI1]
Vendor = E-mu
Product = EMAX II HD
SectorSize = 512
```

## 🧪 TESTNING

### Test 1: Verifiera Config
1. Skapa en bootable disk med OS
2. Kontrollera att `zuluscsi.ini` finns på SD-kortet
3. Verifiera att config innehåller `[SCSI0]` med vendor/product/sectorSize
4. Verifiera att config innehåller alla SCSI IDs som används

### Test 2: Verifiera Boot
1. Skapa HD0.hda med OS
2. Kopiera till SD-kort
3. Sätt in i ZuluSCSI Pico
4. Starta EMAX II
5. Verifiera att EMAX II bootar korrekt

### Test 3: Multi-Image Setup
1. Skapa HD0.hda (boot) + HD1.hda (data)
2. Verifiera att config innehåller både `[SCSI0]` och `[SCSI1]`
3. Testa boot med båda bilderna

## 📝 YTTERLIGARE KONTROLLER

### Kontrollera SD-kort:
1. **Filstruktur:**
   - `HD0.hda` finns (boot disk)
   - `zuluscsi.ini` finns
   - Filnamn matchar ZuluSCSI convention (HDx.hda eller HDx_y_label.hda)

2. **ZuluSCSI Config:**
   - `EnableParity = 1` (kritiskt för EMAX II)
   - `SelectionDelay = 255` (rekommenderat för EMAX II)
   - Varje SCSI ID har vendor/product/sectorSize

3. **Boot Disk (HD0):**
   - Innehåller OS (cluster 1)
   - FAT entry 1 = 0x7FFF (END marker)
   - Catalog entry har field C = 0x0081 (CRITICAL)

---

## 🚨 VANLIGA PROBLEM

### Problem: "EMAX II hittar inte disk"
**Lösning:**
- Kontrollera att `zuluscsi.ini` finns på SD-kortet
- Kontrollera att `SelectionDelay = 255` i config
- Kontrollera att SCSI ID 0 har korrekt vendor/product

### Problem: "EMAX II bootar men hittar inte OS"
**Lösning:**
- Kontrollera att HD0.hda innehåller OS (cluster 1)
- Kontrollera att FAT entry 1 = 0x7FFF
- Kontrollera att catalog entry har field C = 0x0081

### Problem: "ZuluSCSI blinkar men EMAX II svarar inte"
**Lösning:**
- Öka `StartupDelay` i zuluscsi.ini (t.ex. 100-500ms)
- Kontrollera att `EnableParity = 1`
- Kontrollera SCSI-kabel och strömförsörjning
