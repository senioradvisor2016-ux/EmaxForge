# Prompt för Open Claw — EMAX II Boot Problem

## Kontext

Jag arbetar med EmaxForge, en macOS-applikation för att hantera EMAX II disk images och ZuluSCSI Pico. Appen skapar bootable disk images (.hda filer) som ska användas med ZuluSCSI Pico för att boota EMAX II samplers.

## Problem

**ZuluSCSI och EMAX 2 bootar inte korrekt** när disk images skapas med appen.

## Identifierat Problem

### Huvudproblem: ZuluSCSI Config Generation

**Problem:**
- `zuluscsi.ini` genererades med en minimal, ofullständig config
- Config innehöll bara `[SCSI1]` utan vendor/product/sectorSize
- Config saknade `[SCSI0]` för boot disk (HD0)
- Config genererades inte för alla SCSI IDs när multi-image setup används

**Kod som var problemet:**
```swift
// FÖRE (felaktig):
let minimalConfig = """
; ZuluSCSI config for EMAX II
[SCSI]
EnableParity = 1

[SCSI1]

"""
try minimalConfig.write(to: configURL, atomically: true, encoding: .utf8)
```

## Lösning Implementerad

**Fix:**
- Använder nu `ZuluSCSIConfigService.generateConfig()` istället för minimal config
- Genererar config för alla SCSI IDs som används (0, 1, 2, etc.)
- Inkluderar korrekt vendor/product/sectorSize för varje SCSI ID

**Ny kod:**
```swift
// EFTER (korrekt):
let configService = ZuluSCSIConfigService()

// Build list of all created images for config generation
var createdImages: [DiskImage] = []
for i in 0..<count {
    let currentScsiID = count > 1 ? i : scsiID
    let filename = count > 1 ? "HD\(currentScsiID).hda" : previewFilename
    let imageURL = destDir.appendingPathComponent(filename)
    
    if let image = try? DiskImage.parse(url: imageURL, device: appState.currentDevice) {
        createdImages.append(image)
    }
}

// Generate proper config with all SCSI IDs
let configContent = configService.generateConfig(for: appState.currentDevice, images: createdImages)
let configURL = destDir.appendingPathComponent("zuluscsi.ini")
try configContent.write(to: configURL, atomically: true, encoding: .utf8)
```

**Korrekt zuluscsi.ini ska nu innehålla:**
```ini

[SCSI0]

SectorSize = 512

[SCSI1]
Vendor = E-mu
Product = EMAX II HD
SectorSize = 512
```

## Verifierat Korrekt

Följande delar är redan korrekta och behöver inte ändras:
- ✅ Boot signature (standard tools-verifierade värden, size-specific)
- ✅ OS placement (OS skrivs till cluster 1)
- ✅ FAT entry (FAT entry 1 = 0x7FFF, END marker)
- ✅ Catalog entry (Field C = 0x0081, CRITICAL flag)

## Testning

För att verifiera fixen:

2. Kontrollera att `zuluscsi.ini` finns på SD-kortet
3. Verifiera att config innehåller `[SCSI0]` med vendor/product/sectorSize
4. Verifiera att config innehåller alla SCSI IDs som används
5. Testa boot på EMAX II med ZuluSCSI Pico

## Ytterligare Information

- **ZuluSCSI File Naming:** HDx.hda (x = SCSI ID 0-6)
- **Multi-image:** HDx_y_label.hda (x = SCSI ID, y = image index)
- **Boot Disk:** Måste vara SCSI ID 0 (HD0.hda)
- **EMAX II Boot:** Bootar alltid från SCSI ID 0
